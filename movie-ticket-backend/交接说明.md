## 三、怎么把代码传到 GitHub（网页操作，不用命令行）

### 第 1 步：确定传到哪个分支

**强烈建议传到 `lzx` 分支**，因为：
- 那是目前最新、最完整的代码
- 你的后端正是在它的基础上做的持久化改写
- 传到 `main`（空的）别人看不到你的工作

### 第 2 步：打开上传页面

在浏览器地址栏输入（注意中间有个 `/upload/`）：

```
https://github.com/Supviva/Movie-Ticket-System/upload/lzx
```

### 第 3 步：拖文件进去

打开你电脑上的这个文件夹：

```
movie-ticket-backend
```

**把这个文件夹整个拖进网页的上传区域。**

> ⚠️ 注意：网页上传时，拖文件夹进去，GitHub 会自动保留里面的目录结构。
> 如果拖不进去，就先进文件夹，把 `database`、`src` 和几个文件全选后一起拖。

### 第 4 步：填写提交说明

页面下方有个输入框，填：

```
后端：MySQL 持久化层（账号/影片/影厅/场次/选座/购物车/订单/会员）
```

然后点绿色的 **「Commit changes」** 按钮。

### 第 5 步：验证

回到 `https://github.com/Supviva/Movie-Ticket-System/tree/lzx`，
刷新页面，应该能看到 `movie-ticket-backend` 文件夹。

## 四、如果拖拽不成功（备用方法）

网页上传有时对文件夹不友好。备用办法：

1. 打开 `https://github.com/Supviva/Movie-Ticket-System/tree/lzx`
2. 点 **「Add file」** → **「Upload files」**
3. 先把 `database` 文件夹里的两个 `.sql` 拖进去 → Commit
4. 再进 `src/main/java/...` 逐层建目录 → 上传 `.java` 文件

这个办法慢，但一定能成。**如果卡住了，把网页截图发我，我告诉你点哪里。**

### 你想自己再跑一次的话

双击或在项目目录执行：

```bash
java -jar target/movie-ticket-backend-1.0.0.jar
```

程序会自动清理上次的测试痕迹再跑，**可以无限次重复运行**，不会报错。

> 如果命令行里 `java` 找不到，用完整路径：
> `D:\bin\java.exe -jar target/movie-ticket-backend-1.0.0.jar`

### 万一要重建数据库

```bash
mysql -uroot -p < database/01_schema.sql
mysql -uroot -p < database/02_seed.sql
```

密码已写在 `src/main/resources/db.properties`，直接回车输密码即可。

## 七、我做了什么（技术要点）

- **9 张表 + 4 个视图** 的建表脚本，含外键、索引、CHECK 约束
- **7 个 DAO**，全部用 `PreparedStatement` 占位符传参（防 SQL 注入）
- **事务控制**：`Db.inTransaction` 统一处理提交与回滚，连接用 ThreadLocal 绑定
- **抢座防超卖**：下单前 `SELECT ... FOR UPDATE` 锁定座位行
- **占座口径统一**：写进数据库视图 `v_sold_seats`，取消订单只需改状态
- **口令安全**：SHA-256 摘要存储，不存明文
- **金额精度**：全用「分」存 INT，折扣用 BigDecimal 计算
- **验证程序**：8 步 39 项断言，带启动前自清理，可反复运行

代码总量：25 个 Java 类，约 3100 行。

## 八、两个可以提的真实发现

   我的工程用 `release=17`，已经在你机器上编译通过。

   可以告诉他们 9 月 8 日有人把 `main` 的文件删光了，代码都在 `lzx` 分支上。

## 九、特别注意：密码不要提交到 GitHub

`src/main/resources/db.properties` 里有你的 **MySQL 密码**。

**上传到 GitHub 前，建议先把这一行改成占位符**，改成：

```properties
db.password=你的密码
```

这样别人拿到代码不会看到你的密码，也不会误连你的数据库。

> 如果已经上传了也别慌，改成占位符再提交一次就行。
